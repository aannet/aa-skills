# Structure and tone

This guide follows the four principles of ISO 24495-1 (plain language). The reader finds what is relevant. The reader finds it fast. The reader understands it at the first read. The reader can use it.

## Order

- Start with the answer, the decision or the action.
- Put the most important information at the top of the page and at the top of each section.
- Put detail, exceptions and method after the main message.
- Remove what does not help the reader to understand or act.

## Titles

- Write a title that states the message, not the topic.
- Write "Les retards ont doublé en 3 mois", not "Analyse des retards".
- Write the title in words that the reader uses.
- A title that code computes (a template with a value) follows the same rule. Edit the template.

## Sentences and paragraphs

- Write one idea in each sentence. Aim for about 20 words.
- Write one main idea in each paragraph.
- Use the active voice. Put the subject first, then the verb, then the object.
- Replace an abstract phrase with a concrete action.
- Avoid double negatives and vague conditionals.
- Keep the precision that the task needs. Short is not the goal. Clear is the goal.

## Lists and emphasis

- Use bullets for parallel items.
- Use a numbered list only for a sequence of actions.
- Bold only what is critical: a deadline, an obligation, an amount, a risk, an action.
- Write a link text that says where the link goes. Never write "cliquez ici".

## Action

- Start an action with a clear verb: "Envoyez", "Vérifiez", "Choisissez".
- Say who acts, what to do, and by when.
- Show the deadline, the documents needed and the consequence.
- Put the steps in the real order of work.

## Tone

- Be direct, concrete and respectful.
- Use "vous", unless the user asks for another form.
- Do not use an administrative, legal or promotional tone.
- Do not hide a difficulty. Do not promise what is not certain.
- Use the same term for the same idea in the whole deliverable.

## What to cut or move

| Item | Action |
|---|---|
| Repeated information | Cut |
| Internal detail of the method | Move to the detail layer |
| Defensive phrases | Cut |
| Exceptions that touch few readers | Move after the main message |
| Context that the reader already has | Cut |
