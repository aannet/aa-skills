# Audiences

The skill has two reader levels. The level sets how much detail the reader sees at the first screen. The detail layer is always there.

## Levels

| | Manager | Direction |
|---|---|---|
| Question the reader asks | What do I handle now? | What do I decide? |
| Content | Message, split, items to handle | 3 to 5 messages, verdict first |
| Figures | Whole numbers. Exact counts in the detail | Rounded. Comparisons. Trends in words |
| Vocabulary | Business terms kept. Technical terms explained | No tool term, no process term |
| Tables | Allowed. 7 columns or fewer | Rare. 5 columns or fewer |
| Action | Who, what, by when | Decision asked, stake, deadline |
| Edit mode | In place on the source | Impact report first. Then approved changes only |

The budgets are a starting point. The user can change them.

## Choose the level

1. Use the level in the invocation argument.
2. If there is none, read the deliverable. Who reads it? What do they do with it?
3. If it is still not clear, ask one question: manager or direction.
4. If the user does not answer, use `manager`.

## Manager level

- Keep the structure of the deliverable. Simplify its content.
- If the number budget and the structure conflict, the budget wins. Name each removed block in the report.
- Keep the business terms that the manager uses.
- Keep exact counts where the manager must handle each item.
- Move method, thresholds and formulas to a detail layer.

## Direction level

- Open with the verdict in one sentence.
- Give 3 to 5 messages. Each message has one figure at most.
- Compare: to last period, to a target, or to another group.
- State the decision and the deadline.
- Never double the full deliverable. See "Direction level" in `SKILL.md`.
- If the brief names several readers, write for the least technical one.
- Replace tool words with plain words, unless the brief shows that this reader uses them. List the doubtful terms as open questions.

## Impact report template

Use this form for the direction level. Start with one line: the source files that you would edit.

An element is one block: a table, a chart, a group of KPIs or a section. Group the blocks of one view in one row if they change in the same way. Aim for about 20 rows.

| Element | Change | The manager loses / finds | Effort | Check needed |
|---|---|---|---|---|
| (name of the block, table or chart) | one or more of: removed, rounded, grouped, renamed | (what changes for the manager) | low / medium / high | (yes / no, and by whom) |

After the table, add:

- The 3 main gains for the reader.
- The risks, if any.
- The question to the user: which changes to apply.
